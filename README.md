# GTINCode

調剤在庫マスタ／ヒート GTIN カード印刷ブックを自動生成する Excel VBA マクロ集です。

白紙のブックでマクロを実行すると、5 枚のシートを一括生成し、Web 上に公開されている GS1 コード一覧を Power Query で取り込みます。ヒートの GS1 コードを入力するだけで、薬剤名・JAN バーコード・画像ファイル名が自動で揃います。

## 構成

| ファイル | 内容 |
|---|---|
| `mdlBuild.bas` | ブック生成マクロ本体（`BuildWorkbook`）。5 シートのレイアウトと数式を構築します。 |
| `mdlMaster.bas` | 医薬品マスタ取込（`RefreshDrugMaster`）。Power Query のクエリを組み立てて実行します。 |
| `mdlBarcode.bas` | GS1 データバー限定型エンコーダ。ワークシート関数 `DataBarLimitedBits` を提供します。 |
| `mdlPhoto.bas` | ヒート画像の取込（`AssignHeatImage`）。ファイルを選ぶだけでリネームして画像フォルダへ格納します。 |
| `mdlImport.bas` | ヒート画像の配置（`ImportHeatImages`）。G 列のフルパスから画像を読み込み、カード印刷シートに配置します。 |

## 生成されるシート

| シート | 役割 |
|---|---|
| データ | 入力用。C 列に GTIN を入れると他は自動で埋まります。 |
| 命名規則 | 画像ファイルの命名規則と運用手順のドキュメント。 |
| バーコード計算 | GS1 データバー限定型の 74 モジュール展開（編集不要）。 |
| カード印刷 | A4 縦 1 ページに 20 枚のカードを実寸で配置。 |
| 医薬品マスタ | Power Query が Web から取り込む GS1 コード一覧（約 42,000 件）。 |

## データの流れ

```
Web上のGS1コード一覧 (xlsx)
        │  Power Query
        ▼
  医薬品マスタ シート … キー: 調剤包装単位コード 13桁
        │  XLOOKUP
        ▼
  データシート C列(GTIN-14 手入力)
        ├─ D列 検算        … 桁数とチェックディジット
        ├─ E列 13桁        … 先頭0を除いた13桁（マスタ照合キー）
        ├─ B列 薬剤名      … マスタから自動取得
        ├─ F列 ファイル名  … GTIN14_薬剤名.jpg
        └─ G列 フルパス    … 画像フォルダ + ファイル名
        │                        ▲
        │                        │ AssignHeatImage
        ▼                   ダウンロードフォルダの写真
  バーコード計算 → カード印刷 ◀── ImportHeatImages
```

ヒートに印字される GS1 の `(01)` から先頭 0 を除いた 13 桁は、医薬品マスタの「調剤包装単位コード」と一致します。これをキーに突合しています。

## セットアップ

1. Excel で新規ブック（白紙）を作成します。
2. `Alt` + `F11` で VBE を開きます。
3. 「挿入」→「標準モジュール」で 5 つのモジュールを作り、各 `.bas` の内容を**コピー＆ペースト**します。
4. ブックを **マクロ有効ブック（.xlsm）** として保存します。
5. `Alt` + `F8` から `BuildWorkbook` を実行します（マスタ取込を含めて 10 秒ほどかかります）。

> **注意**: VBE の「ファイルのインポート」ではなくコピー＆ペーストを使ってください。`.bas` は UTF-8 ですが、インポートは Shift-JIS として読むため日本語が化けます。

## 使い方

1. ヒート（PTP シート）の `(01)` の後ろの 14 桁を、データシートの C 列に入力します。
2. D 列の検算が `OK` になると、B 列に薬剤名が自動で入ります。`NG` の間はバーコードも描画されません。
3. ヒートを撮影し、ダウンロードフォルダなどに置きます。**手でリネームする必要はありません。**
4. 対象行を選んで `AssignHeatImage` を実行し、写真を選びます。F 列の名前へリネームして画像フォルダへ格納されます。
5. 続けて「カード印刷シートに配置しますか」と聞かれるので「はい」を選びます。
6. カード印刷シートで `Ctrl` + `P`。A4 縦 1 ページに 20 枚印刷されます。

### 画像まわりのマクロ

| マクロ | 動作 |
|---|---|
| `AssignHeatImage` | 選択行に画像を割り当てます。複数行を選ぶと行ごとに順番にダイアログが出ます。 |
| `AssignMissingHeatImages` | 画像が未配置の行だけを上から順に処理します。 |
| `ImportHeatImages` | G 列のパスから画像をカードへ配置し直します。 |
| `OpenImageFolder` | 画像フォルダをエクスプローラで開きます（無ければ作成）。 |

ファイル選択ダイアログはダウンロードフォルダから開きます（レジストリを見るので移動していても追従します）。2 行目以降は前回選んだフォルダから開きます。

画像は既定では**コピー**され、元ファイルは残ります。取り違えてもやり直せるようにするためです。移動にしたい場合は `mdlPhoto.bas` の `MOVE_AFTER_STORE` を `True` にしてください。

格納先フォルダが存在しない場合は自動で作成します（多階層でも可）。

### 設定欄（データシート右上）

| セル | 内容 |
|---|---|
| J1 | 画像フォルダのパス |
| J2 | 画像の拡張子 |
| J3 | 医薬品マスタの取込元 URL |

## 医薬品マスタの更新

配布ファイル名には年月日が入るため、新しい版が出たら J3 の URL を書き換えて `RefreshDrugMaster` を実行してください。シート・クエリごと作り直されます。

URL を変えずに再取得するだけなら「データ」タブの「すべて更新」でも構いません。

ネットワークに繋がらない等で取込に失敗した場合は、ヘッダだけの空テーブルが作られます。数式は壊れず、B 列が「該当なし」になるだけなので、あとから `RefreshDrugMaster` で復旧できます。

## 数式の貼り直し

`RepairDataFormulas` は、データシートの B / D / E / F / G 列の数式だけを貼り直します。C 列の入力値と設定欄（J1〜J3）は保持されるので、**ブックを作り直さずに数式の修正を取り込めます**。

## トラブルシューティング

### 画像を格納したのに「見つからないファイル」と言われる

**J1（画像フォルダ）の末尾に `\` が無い**と、G 列のフルパスが `...\ヒート画像04987....jpg` のように区切り文字なしで連結され、実際の格納先と食い違います。格納側はパスを正規化するため**ファイル自体は正しい場所にある**という、気づきにくい症状になります。

現在は数式側で吸収するようにしたので、末尾の `\` は有っても無くても動きます。拡張子 J2 の先頭のドットも同様です。

**既に作成済みのブックを直す場合**は、次のどちらかで対応してください。

- `RepairDataFormulas` を実行する（C 列の入力値と設定欄は保持されます）
- J1 の末尾に `\` を手で足す

### パスが長すぎる

Windows の従来パス長は 259 文字までです。薬剤名が長い品目があるため、画像フォルダは浅い場所に置いてください。上限を超える場合は格納時に文字数付きで拒否されます。

## 印刷レイアウト

カード印刷シートは A4 縦 1 ページに 4×5 = 20 枚を**実寸**（`Zoom = 100%`）で配置します。

プリンタには固有の印刷不可領域があり、「用紙幅 − 余白」では収まりません。そのため実際の改ページ位置を見ながら、1 ページに収まる最大の余白を自動で選びます。プリンタを変えた場合は、そのプリンタを既定にしてから `BuildWorkbook` を再実行してください。

| 項目 | 値 |
|---|---|
| カード 1 枚 | 45.5 × 52.2 mm |
| バーコード | 26.1 mm（74 モジュール、倍率約 107%） |
| バー高さ | 22.9 mm |
| クワイエットゾーン | 左 9.5mm / 右 9.9mm |
| 1 モジュール | 1pt = 0.353 mm |

## バーコードについて

印字するのは **GS1 データバー限定型**（GS1 DataBar Limited / ISO/IEC 24724）です。医療用医薬品の**調剤包装単位**、つまりヒートに印字されているものと同じ symbology で、`AI (01)` + GTIN 14 桁を符号化します。

JAN/EAN-13 ではありません。EAN-13 は形式としては正しく作れますが、調剤監査システムは GS1 データバーを前提にしているため読み取れないことがあります。

### 実装と検証

エンコードは [mdlBarcode.bas](mdlBarcode.bas) の `DataBarLimitedBits` が行います。ワークシート関数として使えます。

```
=DataBarLimitedBits("04987080908647")   →  74 文字のビット列（1=バー 0=スペース）
```

実装は [BWIPP](https://github.com/bwipp/postscriptbarcode)（Barcode Writer in Pure PostScript）を参照実装として、**7 つのデータ文字グループすべての境界値を含む 145 パターンで出力が完全一致すること**を確認しています。

### 規格上の制約

GS1 データバー限定型は GTIN の**先頭桁が 0 または 1** のものだけを扱えます。調剤包装単位のコードは先頭 0 なので通常は問題ありませんが、該当しないコードを入れた場合は「バーコード計算」シートの長さ検証に `NG 先頭桁が0か1でない` と表示され、カードにはバーコードが描画されません。

## レイアウト定数

`mdlBuild.bas` 冒頭の `Public Const` で調整できます。

| 定数 | 既定値 | 意味 |
|---|---|---|
| `N_ITEMS` | 20 | 品目数 |
| `CARD_W` | 129 | カード幅（列数）= 45.5mm |
| `CARD_H` | 26 | カード高さ（行数） |
| `COLS_N` | 4 | 横に並べる枚数 |
| `GAP_R` | 4 | 段間の行数 |
| `START_C` / `START_R` | 2 / 2 | 開始列・開始行 |
| `BC_OFS` | 17 | バーコード左オフセット |

## 動作環境

- Microsoft Excel（Windows 版、VBA 有効）
- **Microsoft 365** — `XLOOKUP` / `LET` / `MAP` / `LAMBDA` / `SEQUENCE` / `TEXTJOIN` を使用します
- Power Query（Excel 2016 以降に標準搭載）
- 医薬品マスタ取込時のみインターネット接続

## 注意事項

本ブックは棚札・目視確認補助用です。調剤監査は必ずヒート実物の GS1 コードで行ってください。同じ薬剤名でもメーカー・規格・包装単位ごとに GTIN は異なります。
